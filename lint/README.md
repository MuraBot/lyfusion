# lint 规则清单

我们自己积累的 lint 规则(Lily 2026-11-15 定：从现在开始积累)。目的：同一类问题第二次出现时，由检查接住、交给自动修，不再靠 lead 看 diff 才发现。每条规则都不花 lead 调用。

## 文件
- `common.md`:跨语言的规则
- `python.md`:Python(引擎、测试)
- `typescript.md`:TypeScript(Fusion 栏 mod `plugin/hooks/register.tsx`)

以后加了别的语言，就再加一个文件。

## 每条规则怎么接住(按优先顺序)
1. **现成工具**:ruff、`claude plugin validate` 等已有的规则，打开或加参数就能用。
2. **自写检查**:现成工具没有的，写成小脚本，接在项目的 lint 命令后面(`fusion/config.json` 的 `lint`)。引擎每次都会跑 lint,没过就交给自动修。
3. **提示词**:写不成检查的，写进 `WORK_RULES`、模型备注或 `LEAD_GUIDE`。
4. **引擎的禁止规则**:只看"这次新增的行"才能判断的，写进 `fusion/config.json` 的 `forbidden`(where 写 `diff`)。注意：这类命中算违规，要 lead `--waive` 才能验收，不会交给自动修。

## 怎么加一条
- 来源：修改意见、验收后 lead 手改、看护和体检的发现。
- 第一次出现就记进清单。能零误报地查出来就实现(检查不花 lead 调用);查不准的先写进提示词。
- 每条写：问题、出现记录(任务和日期)、怎么接住、状态。状态只用这三种：**已生效**、**待实现**、**只能提示**。
- 版本收尾时统一过一遍：引擎的事件里存着每次修改意见的原文，从里面挑出能变成检查的。
- 规则和检查脚本里不写真实用户名、密钥这类敏感信息，需要时运行时从环境变量取。

## 范围
目前只用于 lyfusion。以后有第二个项目要用，再提出来放到工作区共用(和"代码库"的讨论一起定)。
