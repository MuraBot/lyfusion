# 更新简报:v4.2.1 速度档(2026-11-06)

> Lily 在 Codex 桌面应用里看到快速档"1.5 倍速度、用量更多",问派工脚本能不能开。HEX 的 Codex 额度从没超过 15%,她想试试快速档。

## 查到的
- Codex CLI 0.166.0 自带的模型目录里,gpt-6-luna 有一档 `"id": "priority"`、`"name": "Fast"`、`"description": "1.5x speed"`
- 官方配置文档:`service_tier` 填 `fast`,请求里对应 `priority`;功能开关 `fast_mode` 默认已开;能不能用还取决于模型和账号
- 实测(2026-11-06,gpt-6-luna,推理强度 low,一句话的提示):
  - `-c service_tier=fast`:正常完成,没有警告
  - `-c service_tier=bogus_tier`:Codex 发一条错误事件"is not advertised as supported … will be omitted from requests",然后照常用标准速度跑完
- 用量具体多多少,官方文档没写;第三方说法是 1.5~2.5 倍,没有官方来源

## 改了什么
- 派工脚本新增项目设置 `$ServiceTier`,默认留空(标准速度)。填 `fast` 就给每次 Codex 调用加 `-c service_tier=fast`,探索、实现、续用都算
- 台账每次运行多记一个 `tier`;运行结束的汇总显示推理强度和速度档
- 模型不支持所填的速度档时,脚本打警告"这次用的是标准速度"(Codex 自己只发一条错误事件,不会停)
- `dispatch.md`:速度档开不开问 Lily;`models/gpt-6-luna.md` 记了快速档

## 项目里怎么开
在 `tools/codex-dispatch.ps1` 的"项目设置"里改成 `$ServiceTier = "fast"`。HEX 要先按 `2026-11-05-v4.2-hex-feedback.md` 迁移到 v4.2,再改这一项。
以后比较速度和用量时,看台账的 `tier`。快速档的数据不要和标准速度的混在一起看。
