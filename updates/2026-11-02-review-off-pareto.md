# 更新简报:Codex 审查默认关闭、台账记差值、帕累托查看器(2026-11-02)

> 来源:小熊蜂蜜罐对比实验(`C:\AI WithMe\bear-compare\`,同一个任务交给 ① Opus 单 agent、② Opus lead + gpt-6.1-sol、③ Opus lead + gpt-6-luna)。
> Lily 的决定:Codex 审查先默认全关;改几轮、什么时候停由 lead 判断;简报按级别设行数上限(L3 40 行、L2 60 行);按 API 价格做帕累托曲线。

## 一、实验里查到的事实
- **② 也挂住了,只是没被发现。**脚本记台账的时间比 Codex 最后一条事件晚 7、25、18 分钟:76 分钟里约 50 分钟在白等。③ 的 lead 结束了进程,所以发现了。挂住和模型无关(两组都有网络超时),根因见 ③ 的 lead:Codex 启动时后台拉插件市场,拉取进程占着输出管道。**还没修**。
- **台账重复计算,两组都有。**`codex exec resume` 报的是会话累计用量:③ 助手的读数 233 万 → 762 万 → 950 万 → 1,299 万。按差值,② 的 Codex 实际输入约 281 万,③ 约 1,466 万。
- **续用的审查会话:**② 的真的重新查了,③ 的只复述了上一轮报告。
- **lead 是大头。**按 API 价格粗估:① 约 $2.64;② Codex $1.05 + lead $3.47;③ Codex $0.33 + lead $11.09。lead 的数是估算,见第四节。

## 二、改了什么
- **Codex 审查默认关闭**(`dispatch.md`"审查与修改"):默认由 lead 审,对照设计稿看截图,读最终报告和 `git diff --stat`。数据安全、并发、跨模块接口、存档格式这类高风险模块,lead 再开 `-Review`。改几轮由 lead 判断。删掉了 sonnet 对照审查和"连续 2 次换审查会话"两条。
- **审查每次新开会话:**`-Review -Resume` 由派工脚本拒绝。
- **台账记差值:**`ledger.py record` 发现同一会话的读数都不小于上次的累计值,就记差值,累计值另存在 `cum`。派工脚本的汇总改成"会话累计"。
- **L3 简报写得更少:**`dispatch.md` 的 L3 一行加上"阶段可以只写 1 个,不写实现建议"。行数上限由 LiEC 的 `brief.py check` 检查。
- **新命令 `ledger.py score`**:记 Lily 的交付分和作品分(1~5)。`ledger.py lead` 新增 `--context` 和 `--cost-usd`(拿不到 token 拆分时的估算,方法写在 `--note`)。
- **新文件 `viewer/pareto-viewer.html`**:选一个实验文件夹,它读每个子文件夹的 `ledger.jsonl`,按价格表算美元花费,画出分数和花费的散点和帕累托前沿。价格表可以改;旧台账里的累计读数会自动换算成差值。

## 四、lead 的花费为什么是估算
Claude 应用的用量工具只给上下文大小和额度百分比,没有输入、缓存、输出的拆分;脚本又不能读 Claude 的记录。实验里的估算:调用次数 ≈ 会话消息数 / 2,每次读一遍平均上下文(缓存价),新增上下文写一次缓存,输出按每次 300 token 猜。只当量级参考。要更准,需要一个能给出 token 拆分的来源。
