## 已定
- 依据:`design/v5.0.0-aq.md` §9.1(按模型记的全部规则)、§6(审查包)、§3(退出码)。照写的做,不要另找做法,不要为旧写法留兼容层(§9.1 写明的旧格式读取除外)
- 接口:`fusion/local.json` 的 `sidekick = {"model": 名字, "models": {名字: {"effort": 档位或 null, "fast": 布尔}}}`;CLI 加 `fusion-core config model 名字`、`config effort 档位`、`config fast on|off`(后两个只改当前模型),`config get`、`config set` 保留;`commands/fusion.md` 的 model、effort、fast 三行改成调这三条
- 要修的 5 个问题:
  - 报告格式:`report_schema.json` 改成 OpenAI 结构化输出的严格格式:每个 object 都写 `"additionalProperties": false`,`required` 列出全部属性。questions 的元素 `{text: string, blocking: boolean}`;choices 的元素 `{what: string, why: string}`。现在 choices 的元素是没有属性的空对象、questions 的 `blocking` 不在 required 里,真 Codex 会拒绝或只能输出空对象。`supervisor.finish_run` 的 `question_asked` 只记 text 和 blocking
  - 长时间无进展:`cli._wait` 只看这次等待开始之后新出现的信号。现在只看任务的最后一条信号,上次因 stalled 退出后,再跑同一条命令会被那条旧信号立刻打断
  - 台账:`views.ledger` 补回 lead 和助手的 token(输入、缓存、输出,单位 M),再加助手的模型、effort、fast(从运行事件里取;一个任务用过几种就都列出)。用量现在还记在 `state["usage"]` 里,只是视图没显示
  - `supervisor.integrate` 合并冲突的提示还写着"或者接管",改成"用 fusion-core revise 让助手在最新的主分支上解决"
  - 审查包:停下时第 3 节只写"状态:停下:summary",不要再另写一行同样的"摘要:";做完时照旧写"状态:做完"和"摘要:……"
- 已知的坑:改造现有代码会改掉原有行为,动手前列出要保留的;Codex 沙箱里结束子进程会 Access denied,跑不通的测试用 `-k` 跳过并在证据里写明,派工脚本会在沙箱外跑完整测试
