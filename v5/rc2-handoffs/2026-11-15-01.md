## 4. 坑和方法(本段新发现的)
- **前台命令超时不会被掐**:Bash 超过 timeout 会自动转到后台(通知里给输出文件),所以前台跑引擎命令没有风险。实现超过 10 分钟就会转后台,那时照旧等通知。
- **强杀等待的 CLI 不影响 Codex**:实测用 Stop-Process 杀掉等待中的 delegate,Codex 照跑;重跑同一条 delegate(rc.1)会接着等,计划不会重复派。租约 30 秒过期。
- **装的还是 rc.1 时这样少调用**:`explore - <<'EOF' … EOF && cat fusion/explore.md` 放前台(timeout 600000),一次拿到探索包;delegate、revise 后面接 `; sed -n '1,/^## 改动/p' fusion/review.md`(或整份 cat);accept 放前台,后面接 `ledger --task T`。
- **rc.1 只收 JSON 计划**:`PYTHONIOENCODING=utf-8 python - > <scratchpad>/plan.json <<'PY' … PY && <引擎> delegate - < <scratchpad>/plan.json`。不加 `PYTHONIOENCODING`,Windows 管道是 GBK,引擎解码失败(反馈第 21 条)。
- **审查包超过 400 行就不附 diff**(T10 就是这样)。这时 `git diff 基 候选` 输出超过约 30KB,会被存成文件,还要再 Read 一次。用 `-- 路径` 分两次拿,或者只拿非测试文件。任务 6 要解决这个问题。
- **`--waive` 不放行没通过的检查**:候选的检查没过,哪怕是偶发失败,accept 也直接拒,只能 revise 一轮让引擎重跑(反馈第 27 条)。
- luna 往 design 文档里写中文时会丢编码,变成一串 `?`(T10 第 1 轮命令表那一行);lint C4 待实现。
- 我手动跑 `hook session-start` 时往库里写了一条 session_id 为空的 `lead_session`(seq 187);T10 之后不会再写了。
- 等后台命令时,桌面端每轮结束都要 wrap_up,相当于多 1~2 次请求;能前台就前台。
- "lyfusion 会话"会往 rc2-brief 提交(fa8bc1c、c76f3ec);自己提交前先 `git status` 看一眼,只 add 自己的文件。
