### 引擎要点
- 模块:`store`(sqlite 事件库,唯一写入口)、`state`(重放)、`validate`、`commands`(lead 的命令,只写"想要什么")、`supervisor`(真正动手:启动 Codex、提交候选、检查、集成、清理、接管)、`codex`、`checks`、`gitops`、`intent`、`prompts`、`views`(三层审查视图、状态、注入、通知、台账)、`tools`(12 个 fusion_* 工具)、`mcp`、`hooks`、`cli`
- 工位 = 项目旁边的 git worktree `<项目>-fusion` + 一个 Codex 会话;会话编号从 `thread.started` 取,存在事件库,lead 不用管续用命令
- 命令行:`fusion-core on|off|status|guide|wait|preflight|plan|intent|delegate|explore|answer|review|request-changes|accept|reject|cancel|takeover|config|ledger|events|tick`
- `fusion-core wait`:阻塞到有需要 lead 处理的事再退出;lead 派工后在 Bash 后台跑它来被唤醒(替代没触发的 monitor)。没有 MCP 服务器时它顺便监督

### 插件和宿主的事实(实测或官方文档)
- 安装:Lily 在桌面应用"插件 → 管理插件"上传 zip(文件在 zip 根目录)。不装命令行、不设用户环境变量。不发布到插件市场
- MCP:工具名 `mcp__plugin_<插件>_<服务器>__<工具>`;**工具在延迟列表里**,要 ToolSearch 加载;启动时会先收到 `server/discover`(回 -32601 即可);`CLAUDE_PROJECT_DIR` 有,工作目录是项目
- 钩子:SessionStart(source=startup 等)、UserPromptSubmit、PreToolUse 的 `additionalContext` 都进上下文;PreToolUse 拿得到 `tool_input.file_path`,不阻止
- monitor:进程**拿不到任何环境变量**,命令里写 `${CLAUDE_PROJECT_DIR}` 会被替换;`-p` 非交互模式不启动。桌面会话里探针 monitor 一次都没打印(很可能不启动)
- `bin/` 在 Bash 工具的 PATH 里;命令文件里 `${CLAUDE_PLUGIN_ROOT}` 会被替换
- Codex:`exec resume` 没有 `-s`/`-C`,用 `-c sandbox_mode=…` 和子进程 cwd;支持 `--output-schema`、`--ephemeral`;沙箱下 `.git` 只读,所以提交只能由引擎做;工位不能放系统临时目录(那里可写)
- Windows:在 Claude Code 里起的子进程 `CREATE_BREAKAWAY_FROM_JOB` 能成功
