# v5.0.0-rc.1 设计说明(2026-11-13)

> 短文档,只写 rc.1 相对 aq.2 改了什么、为什么。完整架构仍看 `v5.0.0-aq.md`。rc.1 是用装好的 aq.2 插件迭代 lyfusion 自己做出来的(lead = Claude,助手 = Codex gpt-6-luna);过程和数字在 `v5/progress.md`,lead 的使用体验在 `v5/rc-lead-feedback.md`。

## 1. 设置分三层,每个值只存一处
引擎默认值(`config.py` 常量)→ 项目 `fusion/config.json`(进 git:test、lint、network、干净模式 `clean`、`context_ratio`)→ 本机 `fusion/local.json`(不进 git:开关、助手模型、按模型的 effort/fast/上下文上限、Codex 路径)。一个键只属于一层。按模型的设置在 `sidekick.models.<模型>`。算得出来的值不另存:换工位阈值 = 上下文上限 × `context_ratio`(0 < ratio < 1)。`/fusion` 和 Fusion 栏只改 `local.json`,都走 `fusion-core config`。

## 2. 助手的干净环境和上下文上限
`clean`(默认 true)启动 Codex 时加 `--ignore-user-config --disable apps --disable plugins`,去掉桌面端的 MCP 和插件技能;不读用户配置后,引擎显式传模型、effort、沙箱、service_tier 和 `model_auto_compact_token_limit`(每个模型的 `compact`,默认 400000)。`preflight` 查 Codex 版本、确认这些参数还被认得,不调用模型。

## 3. 看护:慢和卡住
每次运行记统计进台账:用时、命令数、小块读取、重复命令、Codex 版本。运行超过 `watch_minutes`,或小块读取、重复命令超过阈值时,命令以退出码 2 叫醒 lead,附最近命令摘要。运行中 `revise` = 停下这一轮(`interrupt`),按意见接着做,不再悄悄丢掉 lead 的意见。

## 4. 用量按线程求差
Codex `turn.completed` 的 usage 是整个线程的累计值。事件照存原值,重放时按线程求差;旧库重放也自动纠正。上下文估计用本次增量。

## 5. 状态格式版本
`fusion_core.SCHEMA = 2`,`config.json`、`local.json`(顶层 `schema_version`)和 `fusion.db`(`PRAGMA user_version`)共用。缺版本号当 1,自动迁移;比自己新就拒绝(`FormatTooNew`,退出码 2,提示升级插件),不删不改文件。只有旧版本会读错的改动才加 1。

## 6. 提示词体检
- 模型备注:`fusion_core/prompts/models/<模型>.md` 分"给助手""给 lead"两节,项目可在 `fusion/models/` 补充
- LEAD_GUIDE:brief 推荐小标题加"猜测(未证实)""停下的条件";审查包不够看时看工位路径下的文件;加 `ledger`
- 审查包:阻塞问题标"(阻塞)";diff 超上限先附非测试文件;旧测试没过列失败名;助手说测试没过而引擎检查通过时写"以引擎检查为准";候选建不出来时写原因(不再崩)
- WORK_RULES 和 FIXED_RULES 的"不能做的事"从一个列表 `FORBIDDEN` 生成;加 Brief 约定、测试跑法、沙箱说明
- 开工先把 `review.md`/`explore.md` 换成"T编号 第 N 轮:助手还在做"占位

## 7. Fusion 栏(M3,mod)
```text
桌面端输入框下方  ● Fusion  ──点击──▶  输入框上方的面板
                                     开关 · 助手模型 · 思考强度 · 快速档 · 上下文上限
mod(hooks/register.tsx) ──$.process.run──▶ fusion-core config panel | config <动作> | lead-usage
```
- mod 由 lead 写(要读 Claude Code 的类型文件,按规则 Codex 不读),引擎命令走 Fusion
- mod 不写 `fusion/` 下的文件:读用 `config panel`(一行 JSON,只含面板要的字段,不含 env、Codex 路径),改用 `config model|effort|fast|compact|enabled`。校验和格式版本只在引擎一处
- 只用桌面端自带元素(`Box`、`Text`、`Button`、`Select`)和主题色(`claude`、`inactive`、`dimColor`、`warning`、`error`),深浅主题自动适配
- 面板数据在会话开始(或这次加载后第一次画栏)、每轮结束、点开面板和改设置后刷新;不用定时器,不自己开启回合
- 引擎命令失败不藏:只要项目里有 `fusion/`,栏照画;第一次失败弹 toast,面板用 error 色写退出码和原因,只读 `local.json` 显示开关和助手模型,提示改设置用 `/fusion`

## 8. lead 用量(任务 7)
mod 在 lead 跑 explore 和 accept 时把 `$.session.usage()` 原样交给 `fusion-core lead-usage --at explore|accept -`,引擎记 `lead_usage` 事件,只存原始快照。`cost` 是会话累计值,`rateLimits` 是整个账号的,所以:任务的 lead 花费 = 本任务最后一次 accept 快照 − 同一会话里它之前的最后一个 explore 快照;跨会话写"-"。额度百分比只当背景显示。

## 已知问题和留到 rc.2
- Fusion 栏新会话不显示,发出第一条消息后才出现(桌面端发第一条消息才启动引擎)
- mod 没有自动测试;本机没有 TypeScript 和 `claude plugin validate`,类型只按类型文件人工核对,靠 Lily 上传实测
- 手改 `fusion/config.json` 把 `clean` 写成非布尔值时,读取不报错、照 true 处理(`config set` 会拒绝)
- 输出 token 是否已含推理部分 Codex 源码没写明,台账先按"输出 + 推理"相加,可能偏多
- 留到 rc.2:计划接受 Markdown(反馈第 4 条);运行中排队一条补充(第 5 条);按命令种类统计用时;"blocked 但没有阻塞问题"自动续一句(第 11 条)
