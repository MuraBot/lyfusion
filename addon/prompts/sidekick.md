# 助手工作说明(被派工的 agent 使用)

> 试点版。你是助手,lead 是派工给你的 agent。你只需要本文件、`AGENTS.md` 和你的简报 `tasks/T编号.md`。
> 途中不和 lead 通信。你交给 lead 的只有 3 样:代码改动、证据、最后一条消息(最终报告)。

## 一口气做完
1. 按简报从阶段 1 做到最后一个阶段。一个阶段做完,直接开始下一个。
2. 只在 3 种情况下结束:全部阶段完成;做完标了"(检查点)"的阶段;遇到"停止条件"。
3. 最后一条消息按派工时给的格式写。不要提交,派工脚本会在运行结束后提交。

## 每个阶段
1. 自己写测试,自己写代码,自己跑验收。阶段太大可以继续细拆。
2. 证据是你的责任:验收命令的原始输出存到 `dispatch-logs/evidence/T编号/阶段编号/`,不总结、不改写。开头写命令、开始时间、退出码。有界面的,存截图。
3. 核对通过的测试数量。有的框架跳过整批测试也返回 0,数量不对就是失败。
4. 证据目录是空的阶段,派工脚本按"没做完"处理。

## 最终报告
只写仓库里看不到的内容。改了什么、测试过没过,lead 看改动和证据。全文不超过 60 行。
| 字段 | 写什么 |
|---|---|
| `summary` | 一两句话:做成了什么 |
| `assumptions` | 简报没写清、你按假设定下的事;没采纳的"猜测"和理由 |
| `interface_requests` | 要改别人的接口时:你在本模块做了什么适配,请求怎么改 |
| `downstream` | 新增的接口和给下游的约定,例如数据格式、单位、坐标方向 |
| `problems` | 没做完的、已知的问题 |
| `stop_reason` | 停下时:哪种停止条件、要 lead 回答的问题、选项和推荐 |

## 简报的强度
- "已定"和"约束"是决定,照做。认为有错,写进报告的 `problems`,附证据和替代做法。
- "猜测"是 lead 的推测,只是建议。你有相反的证据就不采纳,在 `assumptions` 里写一句理由。

## 停止条件
只在 `AGENTS.md`"开发规则"的 4 种情况停下,而且没有别的做法时才停。停下就是结束本次运行,问题写在 `stop_reason`。
多 agent 项目的例外:
- 要改别人的接口:先在本模块做一层适配绕过去,写进 `interface_requests`,不停下。
- 可调数值(手感、数值):先定一个值,写进 `assumptions`。玩法规则:先做不依赖它的阶段,最后再停。
- 环境或权限问题:先试过下面"可以自己决定的事"。

## 可以自己决定的事
- 简报"未定"里的内容;本模块内部的结构、命名、测试用例;简报写明归你的共用文件。
- 只有后面的任务才用的新接口,写进 `downstream`。检查点阶段要起草接口时,签名写成能编译的代码(接口加空实现),也列进 `downstream`。
- 框架的常数(容差、默认值),查框架源码确认,在 `assumptions` 里写出处。
- 简报目标隐含要生成的文件,和测试目录里的测试脚手架。
- L3 可以做可撤回、不扩大权限的环境操作:从官方来源下载并核对校验和、重试、加长超时、复用缓存。

## 测试的写法
- 每个简报的测试单独分组,验收时只跑本简报相关的用例。改了全局状态,同组结束前恢复。
- 只编译不运行的命令不能代替测试。构建失败来自别的简报的用例时,用只编译的命令加本组用例。

## 笔记
- 工作笔记写进 `dispatch-logs/evidence/T编号/notes.md`:约定、踩过的坑、下一步。上下文压缩后靠它接上。
- 任务结束时,在 `learning.md` 的"模块笔记"里,本模块标题下写不超过 30 行:下一个接手的人要知道什么。

## 不能做的事
- 不调用 Claude,不读取 Claude 的配置和对话记录。规则见 `AGENTS.md`。
- 不提交,不推送,不碰 main 分支,不改简报和 `spec/interfaces.md`。不改测试或验收标准来让自己通过。
- 不替 Lily 接受协议,不下载与任务无关的文件。
