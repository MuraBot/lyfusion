# 助手工作说明(被派工的 agent 使用)

> 试点版。你是助手,lead 是派工给你的 agent。你只需要本文件、`AGENTS.md` 和你的简报 `tasks/T编号.md`。
> 和 lead 交流只用 `tools/mail.py`。不要直接写信箱文件,也不要结束会话来提问。

## 一口气做完
1. 按简报从阶段 1 做到最后一个阶段。写完一个阶段的回报,直接开始下一个阶段。
2. 只在 2 种情况下结束:全部阶段完成,或遇到"停止条件"。
3. 最后一条消息按派工时给的格式写。

## 每个阶段
1. 开始前运行 `python tools/mail.py inbox T编号 --as assistant`。有"停",做完当前步骤就停。
2. 自己写测试,自己写代码,自己跑验收。阶段太大可以继续细拆,在 decisions 里写明。
3. 证据是你的责任:验收命令的原始输出存到 `dispatch-logs/evidence/T编号/阶段编号/`,不总结、不改写。开头写命令、开始时间、退出码。
4. 核对通过的测试数量。有的框架跳过整批测试也返回 0,数量不对就是失败。
5. 运行 `mail.py send T编号 report` 回报。关掉沙箱时提交这个阶段,说明末尾只写一行 `Phase: 阶段编号`,其余由钩子补。开着沙箱时不提交。

## 回报
只写仓库里看不到的内容。改了什么、测试过没过,lead 看改动和证据。
| 字段 | 写什么 |
|---|---|
| `--summary` | 一两句话:这个阶段做成了什么 |
| `--evidence` | 证据文件夹,例如 `dispatch-logs/evidence/T5/1` |
| `--decisions` | 简报没写清的地方你怎么定的;没采纳的"猜测"写一句理由 |
| `--problems` | 卡在哪里,没做完什么。没有就写"无" |
| `--downstream` | 给下游的具体约定,例如数据格式、计算方法、坐标方向。没有就写"无" |
| `--proposal` | 可选。新增的接口写成提案,lead 批准后写进 `spec/interfaces.md` |

文字长或带引号时,先写进文件,再用 `--summary @文件路径`。

## 简报的强度
- "已定"和"约束"是决定,照做。认为有错,提异议。
- "猜测"是 lead 的推测,只是建议。你有相反的证据就不采纳,在 decisions 里写一句理由,不用提异议。

## 停止条件
只在下面 4 种情况停下,而且没有别的做法时才停:
1. spec 里没有的产品决定,例如手感、数值、玩法规则;
2. 会改变其他模块的接口;
3. 环境或权限问题,且下面"可以自己决定的事"都试过了;
4. 同一个问题连续失败 2 次。

L3 简报遇到第 1、2 种时:可调数值先定一个值,在 decisions 里标出;玩法规则发提问,先做别的阶段;只新增的接口自己做,写进 `--proposal`;改变已有接口发提问,等 lead。

## 可以自己决定的事
- 简报"未定"里的内容;本模块内部的结构、命名、测试用例;简报写明归你的共用文件。
- 框架的常数(容差、默认值),查框架源码确认,在 decisions 里写出处。
- 简报目标隐含要生成的文件,和测试目录里的测试脚手架。
- L3 可以做可撤回、不扩大权限的环境操作:从官方来源下载并核对校验和、重试、加长超时、复用缓存。在 decisions 里写明。

## 提问
1. 先查简报、`spec.md`、`spec/interfaces.md`。答案已在那里,就不要问。
2. `mail.py send T编号 question --kind 种类 --text 问题`。种类:可撤回、产品、不可撤回、接口。可撤回的要加 `--assumption`(超时按什么保守假设继续)。
3. `mail.py wait T编号 --reply-to 消息编号`,最多等 10 分钟,不耗 token。超时:可撤回的按假设继续;其他的先做不依赖它的阶段,没有可做的才停。

## 异议
- `mail.py send T编号 objection`,4 项都写:`--claim`、`--evidence`、`--cost`、`--alternative`。
- 默认照原计划继续。涉及正确性或数据安全时加 `--blocking`,等回复。L1、L2 只对事实矛盾提异议。

## 测试的写法
- 每个简报的测试单独分组,验收时只跑本简报相关的用例。改了全局状态,同组结束前恢复。
- 只编译不运行的命令不能代替测试。构建失败来自别的简报的用例时,用只编译的命令加本组用例。

## 笔记
- 工作笔记写进 `dispatch-logs/evidence/T编号/notes.md`:约定、踩过的坑、下一步。上下文压缩后靠它接上。
- 任务结束时,在 `learning.md` 的"模块笔记"里,本模块标题下写不超过 30 行:下一个接手的人要知道什么。

## 不能做的事
- 不调用 Claude,不读取 Claude 的配置和对话记录。规则见 `AGENTS.md`。
- 不推送,不碰 main 分支,不改简报和 `spec/interfaces.md`。不改测试或验收标准来让自己通过。
- 不替 Lily 接受协议,不下载与任务无关的文件。
