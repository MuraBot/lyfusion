# Design Decisions
> The lead edits this file directly. The engine includes the full file with each assignment. Record only decisions that every task must follow.

## rc.1 throughout
1. The engine uses only the Python standard library and sqlite; do not add third-party dependencies. Tests use pytest and the fake Codex (`tests/fake_codex.py`); do not call real Codex or access the network.
2. Do not casually change what the lead sees: the usage guide (`views.lead_guide`, at most 24 lines starting in rc.2), the four actions (explore, delegate, revise, accept), and their output. Change these only when a task explicitly asks for it. Keep new features in the engine so the lead does not need extra calls.
3. **Settings have three layers, and each value is stored in one place** (Lily agreed on 2026-11-13): engine defaults (constants in `config.py`) → project `fusion/config.json` (tracked; project settings such as test, lint, network, clean mode `clean`, and `context_ratio`) → local `fusion/local.json` (untracked; personal choices such as the switch, assistant model, per-model effort/fast/context limit, and Codex path). A key belongs to only one layer; do not override it across layers. Per-model settings go under `sidekick.models.<model>`; unregistered models use defaults. Do not store derived values (for example, worktree rotation threshold = context limit × `context_ratio`). New fields have defaults; old-format or missing-field files load with defaults and do not error.
4. The `/fusion` skill and future Fusion panel change only `local.json`, through `fusion-core config <action>`; project settings belong in `fusion/config.json`. `fusion-core status` shows current values. User-visible text written or rewritten from rc.2 onward is English (see rc.2 decision 1).
5. Do not read `~/.claude/`, Claude folders under AppData, or Codex `auth.json`. The engine does not parse `~/.codex/config.toml`, with the **sole exception** (Lily agreed on 2026-11-14): in clean mode, read only `windows.sandbox` and `sandbox_workspace_write.network_access` and pass them through unchanged with `-c`; do not read or pass any other keys. Remove `CLAUDE*` and `ANTHROPIC*` environment variables before starting Codex or checks. Do not use Codex flags that bypass the sandbox or approval. Second exception (rc.2 task 4): the engine reads `models_cache.json` from the Codex home for model capabilities; it reads nothing else in that folder.
6. The version is `5.0.0-rc.8`: do not change the version in plugin.json, `__init__.py`, the README, `tests/test_shape.py` or `MOD_VERSION` in `hooks/register.tsx`.
7. Existing tests must continue to pass. When changing existing behavior, update the corresponding tests and explain why in the report.
9. State schema version (starting task 4): one number, `fusion_core.SCHEMA`, shared by `config.json`, `local.json`, and `fusion.db`. Increment only for changes old versions would misread; adding fields with defaults or event data fields ignored safely by old versions does not require an increment. When changing the format, update migrations and tests.
8. Test options for this project: add `-n 6` when running a whole test file (`test_cli.py` takes about one minute single-threaded, slower than the roughly 26-second parallel full suite); omit it for a single test. See WORK_RULES for the general test process.
10. Model capabilities (display name, reasoning efforts, Fast Mode, maximum context) come from Codex's own `$CODEX_HOME/models_cache.json` (default `~/.codex/models_cache.json`), read in place and never copied (rc.2 task 4, Lily 2026-11-14). If missing, unreadable, or malformed, use the built-in table and show a warning. For models in neither source, use conservative defaults: efforts low through xhigh, no Fast Mode, and no context limit.
